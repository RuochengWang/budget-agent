# 学校模型真实联调 · 2026-11-17

模型为 `qwen3.8-chat`，请求发送到学校已配置的 OpenAI 兼容接口。
预算、商品/活动查询、优惠求解、欲望/理性/优惠/裁判、交叉回应与最终校验均使用正式实现，未换成脚本角色。
**输入商品仍是仓库中 `is_demo=true` 的样例快照，不是实时电商数据。**

## 可以如何复现

在仓库根目录运行，密钥继续只放本机 `.env`：

```bash
uv run budget-agent check-model --json
uv run budget-agent --config configs/validation.toml run --mode real --case sneakers_wait
uv run budget-agent --config configs/validation.toml run --mode real --case tissue_buy
uv run budget-agent --config configs/validation_cross.toml run --mode real --case tissue_buy
uv run budget-agent --config configs/validation.toml run --mode real --case unknown_shipping
uv run budget-agent --config configs/validation.toml run --mode real --case exact_budget
uv run budget-agent --config configs/validation.toml run --mode real --case missing_profile
```

前一套配置关闭交叉回应，后一套开启唯一的一轮。两套均为请求 90 秒、全流程 540 秒、
工具上限 6 次、格式重试最多 1 次；模型以本机有效配置为准。
`configs/default.toml` 的 45/180 秒和默认关闭交叉回应保持不变。
使用这些命令会真实请求学校模型；缺少必填预算信息时程序直接结束，不发起模型调用。

## 实测暴露并修正的问题

1. **等待时间不足**：健康检查可达，结构化自检一次通过（输入 265、输出 63、共 328 tokens）。
   但完整角色响应曾超过 45 秒；90 秒配置下观测到单次响应约 12.5–75.2 秒。
   原 45 秒配置留下 3 条完整 partial 记录，其余运行中止后重新验收。
2. **正确金额被误判**：“单买 280 元后节省 25 元”不能把前一个 280 当成节省额；
   “原价合计 305 元”应核对折前小计，而不是到手价 255 元。
3. **分单位遗漏**：真实输出常用 `25500分`，现已纳入金额识别与欲望观点裁剪，
   同时排除“20分钟”“4分之一”等非金额表达。
4. **需求事实与假设混淆**：一条重跑记录仅因“组合可能含纸巾”而返回 need_info。
   提示词现明确：候选由用户确认需要；没有组合或库存证据时，用条件句表达疑虑，
   不编造组合内容，也不把假设自动当作关键事实缺失。预算、运费等真正缺失仍必须 need_info。
5. **单买限定与派生预算**：“单独买组合需支付 280 元”仍核对单买价；
   “购买后剩余可支配预算 45 元”由程序检查 `300 - 255 = 45`，与买前预算 300 元、
   购买后现金 945 元区分。错误的到手价 300 元仍被回归测试拦截。

原始输出、错误、用量和校验前后的差异均保留。未用改标签、跳过测试或反复重试连接错误来制造通过结果。

## 后续边界

- 这次证明真实模型与正式模块能够协作，以及相关错误能被定位和复验，不保证每条观点都事实完整。
  早期输出存在对组合内容、库存和消费比例的推测；报告需保留这些质量问题与模型不稳定性。
- 金额文本核对仍是有限规则，不是任意自然语言的事实证明；中文数词、模糊指代和比例需要继续评测。
- 旧提示词下的一条模型原始 need_info，最新 policy 仍保留 need_info；程序不会把所有结论硬改成 buy。
- 本次两个案例可同时进行，因此响应时间不是受控的串行性能对照。服务响应较慢，课堂应准备历史回放。
- E 仍需完成独立测试集、标签、基线与指标；不能将本次开发联调结果写成最终实验准确率。
- `policy_violations` 也记录运费未知、预算缺字段等业务问题，非空不等于模型说错；评测须区分输入缺失与模型违规。
