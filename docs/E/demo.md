## 2. 现场命令（可复制）
```text
# 展示机已由 11/20 彩排准备好；现场不再安装依赖
uv sync --frozen --extra dev --extra ui
uv run budget-agent list-cases
uv run budget-agent run --case sneakers_wait
uv run budget-agent run --case tissue_buy
uv run budget-agent run --mode real --case sneakers_wait   # 预期 partial，退出码 2 是约定
uv run budget-agent replay outputs/<终端打印的 run_id>.json
uv run streamlit run app.py            # 端口占用时加 --server.port 8502
```

- `run` 会把记录保存到 `outputs/<run_id>.json` 并打印路径；`replay` 只读记录、不调用模型。
- 界面顶部「页面」只有两页：**「运行」**（加载开发案例、改表单、运行并保存）与**「历史回放」**（选择 `outputs/` 记录回放，显示「不是本次推理」警告）。
- 不用 uv 的机器：把 `uv run budget-agent` 换成仓库内 `.venv/bin/budget-agent`（Windows 用 `.venv\Scripts\budget-agent.exe`），Streamlit 同理。
- **本机实测（2026-11-20 冻结版本）**：`uv run` 会因 `~/.cache/uv` 只读而报 `Could not acquire lock … Read-only file system`。先 `export UV_CACHE_DIR=/tmp/uvcache` 即可（已验证 `list-cases`、`run` 正常）；现场来不及排查就直接走 `.venv/bin/budget-agent`。
- 冻结版本实测：`.venv/bin/budget-agent list-cases` 输出 10 个开发案例，`run --case sneakers_wait` 打印「建议=wait」，`run --mode real` 在无密钥时打印 `状态=partial` 与"请在本机 .env 中填写 BUDGET_AGENT_API_KEY"。

## 3. 主案例讲法（6 分钟）
### 3.1 sneakers_wait：优惠后仍超预算 → 等待（B，5:00—8:00）
- 输入：现金 1200 元、20 天后拿生活费、每天基本开支 40 元、预留金 100 元、已有一双旧球鞋。
- 基本开支 40×20 = 800；可自由支配 = 1200 − 800 − 100 = **300 元**。
- 球鞋 800 元，满 700 减 150，运费 0 → **实付 650 元**；买后现金 550 <（800+100）→ 不满足预算 → **等待**。
- 讲解：650 元比标价便宜 150 元，但仍高于可支配的 300 元；**优惠不等于买得起**。结论由程序约束给出，四个角色只提观点；证据可在「证据与轨迹」核对 `input:profile`、`product:sneakers`、`promotion:shoes-150`、`offer:chosen`、`budget:final`，本次共 5 次工具调用。

### 3.2 tissue_buy：凑单反而少付 25 元 → 购买（C，8:00—11:00）
- 目标日用品 280 元 + 确实需要的纸巾 25 元 = 305 元；满 300 减 50 → **实付 255 元**；**单买 280 元**。
- 255 < 280，且买后现金 945 ≥ 900 → 满足预算 → **购买**。
- 讲解：比较的是最终总付款（含运费），不是券面值；凑单只在「确实需要」时成立，否则看 `addon_not_worth_it`。

### 3.3 备选案例（每例 40—60 秒）
| 案例 | 一句话讲点 |
|---|---|
| `addon_not_worth_it` | 加 80 元高价凑单品后总额 360、减 50 仍要 **310 元 > 单买 280 元**，程序选单买：凑单 ≠ 更省。 |
| `promo_expired` | 评估时点 2026-12-05 晚于活动截止 2026-12-01，活动不参与计算、证据表没有该活动：不沿用过期优惠。 |
| `unknown_shipping` | 运费未知时只算到「待确认」，状态与建议都是「需要补充信息」：不把未知当 0。 |
| `missing_essential` | 缺少每日基本开支立即需要补充信息，只调用 1 次工具，不默认 0。 |
| `missing_profile` | 预留金留空 = 未提供（不是 0），返回需要补充信息。 |

## 4. 诚实区分演示、正式运行和回放
- **demo**：终端打印「演示替身：脚本角色 + 手工优惠 fixture，不代表真实模型或求解器效果」；记录 `verified=true` 只是手工 fixture 算术复核（`verification_method=demo_fixture`），不证明全局最优，也不验证实时活动。
- **real**：正式界面读取 [A 的验证配置](../../configs/validation.toml)，单次请求上限 90 秒、全流程 540 秒。学校模型的开发案例联调见 [A 的联调记录](../A/live_validation.md)；它不是冻结集成绩。缺本机密钥或接口失败时，不切换到 demo；课堂优先展示真实历史回放，避免等待。
- **历史回放**：界面显示「历史回放：原模式=…，以下内容来自保存的记录，不是本次推理」；回放不调用模型。
- **展示中不能出现**：任何准确率、提升幅度、费用换算；这些留给 11/17—18 真实实验后填入。

## 5. 现场观众输入（3 分钟）
允许在「运行」页表单内改：现金、每日基本开支、固定支出、预留金（元；留空 = 未提供，0 = 确认没有；最多两位小数且非负）、天数（非负整数）、目标商品（仅快照内 4 个商品）、确实需要的凑单品（≤ 8 个、不含目标）、运费（留空 = 未知）、紧迫程度、已有相似物品、购买理由、评估时点。**不新增商品、不新增活动、不抓网页。**

推荐三步：① 观众报现金（如 1600）→ 运行 → 可支配 700 元、实付 650 元、建议购买；② 清空运费 → 运行 → 状态「需要补充信息」、总付款「待确认」；③ 说清三句话：

1. 「演示替身只说明流程怎么衔接，不代表正式算法或模型效果。」
2. 「空白和 0 是两回事：空白是还不知道，0 是确认没有。」
3. 「未知信息如实显示，不显示假的成功；缺密钥或接口失败就显示 partial。」

边界：观众报极端值按表单规则运行，结果为「需要补充信息」也照实展示，不现场改数据掩盖；运行后切换案例时界面会提示「这是历史运行结果，不是当前表单输入」，不要当成新结果。

## 9. 故障预案与切换话术
| 现象 | 动作 | 话术 |
|---|---|---|
| 网络/模型接口失败或超时 | 停止重试，切「历史回放」页或 `replay` | 「正式模型接口此刻不可用；以下展示的是 11/20 冻结版本保存的真实历史记录，不是实时推理，但输入、计算与证据都保留了。」 |
| Streamlit 打不开 / 端口占用 | 换 `--server.port 8502`；仍失败改用 CLI | 「界面暂时不可用，我们用同一条 run_case 入口的命令行展示同一套流程。」 |
| `uv run` 报 `Could not acquire lock` / `Read-only file system` | `export UV_CACHE_DIR=/tmp/uvcache` 后重试；或改用 `.venv/bin/budget-agent` | 「uv 缓存目录不可写，我们直接用仓库自带的虚拟环境跑同一条命令。」 |
| 环境/依赖异常 | 备用机或已同步 `.venv`；再不行播录像 | 「环境故障，以下播放 11/20 彩排录像，内容与冻结版本一致。」 |
| `outputs/` 为空或记录缺失 | 现场重跑 demo（不联网）生成记录再回放 | 「这是刚刚在冻结版本上生成的演示记录，可以现场回放核对。」 |
| 时间不够 | 删第 3.3 节备选案例，保两个主案例与贡献/局限 | 「备选案例与实验数据见报告与仓库文档。」 |
| 观众问模型效果 | 说明只有演示替身，真实基线安排在 11/17—18 | 不报任何未跑出的数字。 |
