# 运行与演示

## 启动

在项目根目录执行 `uv sync --frozen --extra dev --extra ui`，再执行 `uv run streamlit run app.py`。浏览器打开 `http://localhost:8501`。

「运行」页直接选择商品，并填写预算、购买理由和运费。金额以元填写，留空表示未知，填 0 表示已知为零。运行结束后，记录可在「历史回放」页打开。这份指南也可用于 20 分钟的课堂展示。

## 离线复现

| 输入或操作 | 球鞋 | 日用品 |
|---|---|---|
| 目标商品 | 演示球鞋 | 演示日用品组合 |
| 当前现金、剩余天数、每日开支 | 1200 元、20 天、40 元 | 相同 |
| 其余预算字段 | 固定支出 0 元、预留金 100 元 | 相同 |
| 运费 | 0 元 | 0 元 |
| 购买理由 | 想换一双新配色的球鞋 | 日用品快用完，纸巾也确实需要 |
| 确实需要的凑单品 | 留空 | 演示纸巾 |
| 评估日期 | 2026 年 11 月 18 日 | 相同 |

两个案例可支配预算均为 300 元。球鞋实付 650 元，建议等待。日用品单买 280 元，凑单实付 255 元，少付 25 元。离线模式使用脚本判断。历史回放会标明原记录的运行模式。

## 正式模型中的角色回应

按 [启动说明](../../README.md) 配置本机密钥，选择「正式模块」，勾选「一轮角色回应」。参考上方球鞋案例，将现金改成 1600 元，已有物品填「旧球鞋」，购买理由填：

> 旧球鞋晴天还能穿，但雨天容易打滑。周末活动要走很久，我想换鞋，也可能借到一双，只是还没确认。

这组输入可支配预算 700 元，实付 650 元。结果页按初始观点、交叉回应和裁判建议展示。一次实际运行给出「等待」，建议先确认能否借到合适的鞋。新运行应按当次输出解读。

正式运行需要网络和模型服务。现场展示可先保存一条完成的记录，再在「历史回放」中选好备用。仓库提供样例商品、活动和输入，运行记录由本机生成。
