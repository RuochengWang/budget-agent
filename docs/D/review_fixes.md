# D 集成修复 · 2026-11-17

基于已合并 PR #5 的 `cf00ca1` 修复 4 项审阅问题。B/C 的正式预算、商品及优惠求解已合并。

## 改动与交接影响

1. **欲望上下文**：`desire.build_payload()` 改为白名单构造需求、已有物品和非金额商品事实。
   同时裁剪 `case.profile`、请求中的运费、商品价格及嵌套证据；原始上下文保持完整。
   交叉回应复用同一视图，并省略对方主张中的明确数字金额。
2. **引用与原始建议**：`judge.run()` 不再提前删除虚构引用或改写下一步。
   欲望与优惠节点也保留原始引用，交由 policy 记录和阻断；只清理最终决定的非法展示引用。
   交叉回应的混合真假引用整条拒绝，不通过清洗将错误主张伪装成有依据。
3. **交叉回应事实**：理性角色收到完整的最终报价、预算、商品及证据表。
   欲望角色收到裁剪后的事实表；两者都只能引用自己实际收到的证据。
4. **金额含义**：到手价绑定 `payable_cents`、单买价绑定 `baseline_payable_cents`、
   可支配预算绑定 `discretionary_cents` 等。禁止用预算 300 元证明“到手价 300 元”，
   实际付款仍为 255 元时必须拦截。金额解析使用 Decimal，包含零价和负预算。

公共函数签名、schema、依赖、配置默认值不变。B 无需修改预算和理性接口，C 无需修改求解器；
E 仍读取同一份 RunRecord，`proposed_decision` 保留完整原始建议，违规见 `policy_violations`。
演示脚本的欲望引用相应改为只引用需求，继续保持离线演示可运行。
共享协议补充了上下文裁剪、引用留痕与优惠节点预留一次最终预算调用的约定。
