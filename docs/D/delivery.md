# D 部分交付说明

D 的四个角色节点与最终保护已实现。B/C 的正式预算、商品和优惠求解已合并；
原先“B/C 尚未实现、real 在第一步停止”的说明已不适用。
2026-11-17 的审阅修正及验证方法见 [集成修复说明](review_fixes.md)。

## 当前实现

| 文件 | 作用 |
|---|---|
| `agents/desire.py` | 只发送需求、已有物品和非金额商品事实；裁剪嵌套预算数据；保留原始引用供最终检查 |
| `agents/deal.py` | 固定调用查询规则与求解器，生成方案证据，预留一次最终预算复算 |
| `agents/judge.py` | 生成并原样返回 DecisionProposal，最终校验不在此提前清洗 |
| `agents/cross_response.py` | 最多欲望、理性各回应一次；读取各自可见的事实，拒绝复读和非法引用 |
| `decision_policy.py` | 检查引用、购物篮、金额、方案与预算，保留原始建议并记录调整原因 |
| `amounts.py` | 阿拉伯数字金额解析与观点金额省略，使用 Decimal 转整数分 |
| `prompts/*.md` | 明确角色边界、数据与指令区分、事实引用和结构化输出 |

公共函数签名与数据协议不变，接口语义以 [公共约定](../common/contracts.md) 为准。

## 工具额度

全流程上限默认 6 次。A 的预算初算、商品查询占 2 次，优惠节点必须留 1 次给最终预算复算。
优惠节点可用 3 次，固定查询规则与求解使用其中 2 次，正常全流程共 5 次。
额度不足时明确退出，不反复试探；固定序列不能描述为已经完成模型自主工具规划。

## 决策与引用

- `proposed_decision` 保留裁判原始输出；`final_decision` 是程序校验后的结果。
- 不存在的角色/裁判引用会触发 policy 记录；不能在检查前删除后继续放行购买。
- 预算缺失、非法引用等阻断建议；未确认报价等只在购买依赖该事实时阻断。
- 未通过最终付款预算检查的购买建议改为 `wait`；低紧急度且已有同类物品追加替代提醒。
- 明确的到手价、单买价、可支配预算等绑定各自字段，不能把“数字存在”当成“含义正确”。
- 保留相关级问题与否决级问题的区分；违规命中率和动作改变率应分别统计。

## 运行与验证

```bash

uv run pytest

```

脚本模型测试覆盖正式模块衔接和错误分支，不代表真实模型的观点质量。
真实模型应继续验收超预算球鞋、日用品凑单，并分别检查交叉回应开/关的输出、引用与记录。

## 已知限制

1. 金额解析覆盖带阿拉伯数字的元、块、¥/￥，不解析“两百”“三百五”等中文数词。
2. 金额类别核对覆盖常见明确措辞，不是完整语义证明；复杂说法仍需人工抽查。
3. 欲望视图排除结构化预算和工具金额，但用户自由文本可能自行包含数字，不能据此声称所有文本金额均已隔离。
4. 交叉回应默认关闭，需由 A 完成真实模型验收后显式开启；demo 模式仍使用独立演示替身。

报告需明确区分工具计算、固定编排和模型观点生成，保留真实失败与局限，不使用脚本结果宣称模型效果。
